<objective>
Fix the Phase 3 UAT blocker (item 8): refreshing, bookmarking, or deep-linking the Knowledge Library URL renders `<NotFound />` instead of the Library, which cascades into UAT items 9–13 ("Library unreachable → no data → nothing to check").

Root cause (from 03-UAT.md): `useLibraryUrlState.ts:75` writes library view state to the global hash as `#/library?...` via `history.replaceState`. `App.tsx`'s top-level hash router only matches `/`, `/view*`, and `/login`; every other route — including `/library` — falls through to `default → <NotFound />`. Because `replaceState` does not fire `hashchange`, the bug is latent during live in-app navigation but triggers on refresh/bookmark/shared deep-link. Separately, `DashboardPage`'s tab state (`zenView`/`moreTab`) is local React state that always initializes to `"core"`, so even with routing fixed a deep-link would not restore the correct tab.

Fix strategy (interface-first):
1. Create one pure mapping helper `routeToTabState(route)` returning `{ zenView, moreTab }` for dashboard-owned routes or `null` for unknown routes — the single source of truth shared by both consumers.
2. `App.tsx` uses it to route dashboard-owned paths to `<DashboardPage />` while keeping `<NotFound />` for genuinely unknown routes.
3. `DashboardPage` uses it to hydrate initial `zenView`/`moreTab` from the hash.

Do NOT change the hash format `useLibraryUrlState` writes (`#/library?...`) — CommandPalette deep-links (`library?entry=...`) and shareable links depend on it. App.tsx adapts to recognize it.

Purpose: Close the item-8 blocker and unblock re-testing of items 9–13.
Output: A shared route helper, a fixed router, hash-hydrated dashboard tabs, and a re-tested Library.
</objective>
