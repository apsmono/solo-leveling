<objective>
Close the error-handling-chain gaps found in Phase 5 verification (CR-01 → CR-02 → CR-05, plus the WR-02 type symptom). These are surgical, dependency-free fixes that break the failure cascade where an LLM error silently advances the onboarding wizard with a null profile, sticks the submit button, and then drops the profile save — causing a silent re-onboarding loop.

Purpose: A first-run owner whose LLM parse fails must see an error and stay on Step 1, never advance with empty data, never get stuck in "Analyzing...", and never lose their profile silently.
Output: Backend parse-identity returns a proper 502; IdentityBox guards the response and always resets loading; useOnboarding completes safely when profile is null; ProfileData typed correctly.
</objective>

```python
@router.post("/onboarding/parse-identity")
async def parse_identity_endpoint(payload, user=Depends(require_auth)) -> dict[str, Any]:
    text = str(payload.get("text", "")).strip()
    if not text:
        raise HTTPException(status_code=status.HTTP_400_BAD_REQUEST, detail="Missing 'text' in request payload.")
    try:
        parsed = parse_identity(text)
        return {"status": "ok", "profile": parsed}
    except Exception:
        logger.exception("Failed to parse identity")
        return {"status": "error", "message": "Failed to parse identity. Please try again."}  # BUG: HTTP 200
```
