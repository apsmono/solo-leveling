## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /api/v1/onboarding/parse-identity | Free text input crosses here (untrusted) |
| browser -> /api/v1/profile | Profile JSON crosses here (untrusted after edit) |
| parse-identity -> LLM (run_agent) | User text sent to LLM for parsing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | parse-identity free text input | mitigate | LLM parses to structured JSON via constrained system prompt; profile validation rejects malformed responses; no raw text stored as executable content |
| T-05-02 | Tampering | LLM prompt injection via Identity Box | mitigate | System prompt constrains output to JSON schema only; parse_identity() validates/clamps all returned fields (max 3 pain_points, max 3 suggested_apps from allowed list); malformed JSON returns graceful fallback |
| T-05-03 | Elevation of Privilege | Onboarding bypass (skip to data) | mitigate | Backend profile check (GET /profile) is authoritative; frontend state follows backend; no localStorage-only bypass path (D-08) |
| T-05-04 | Information Disclosure | Profile data exposure | accept | Profile contains role + pain points (not sensitive PII); single-owner model; all endpoints require auth |
| T-05-SC | Tampering | npm/pip installs | mitigate | No new packages required (RESEARCH.md Package Legitimacy Audit confirms); existing dependencies only |
</threat_model>
