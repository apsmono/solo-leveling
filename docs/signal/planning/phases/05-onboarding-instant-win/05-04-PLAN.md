<objective>
Close the Instant Win OAuth gap (SC-3 / ONB-03 / ONB-04) via the honest-labeling approach. Phase 5 verification found that the digest always falls back to the cold-start capability preview because no real OAuth handshake is wired to the Connect button, yet the card is labeled "Your first digest / Last 24 hours" — falsely implying live data.

Investigation confirms the brain has NO browser-triggerable OAuth authorization endpoint: the Gmail integration uses `InstalledAppFlow` (desktop/CLI flow) with file-based credentials (`GMAIL_CREDENTIALS_PATH` / `GMAIL_TOKEN_PATH`) established out-of-band, and `auth_session.py` only SYNCS already-existing tokens into n8n. Wiring a real web-OAuth flow is a new subsystem (OAuth client registration + redirect/callback endpoints + per-owner token storage), far beyond a surgical gap-closure fix. Per the gap-closure instructions ("If a real OAuth endpoint exists in the brain, wire it. If not, the honest-labeling approach is the correct gap closure"), this plan implements honest labeling.

Purpose: The owner must never be shown a generated capability preview disguised as a live 24-hour digest. The card must truthfully state whether it is a preview or live data.
Output: The digest endpoint returns a `mode` ("live" | "preview"); `_query_connected_sources()` is extended so any integration with live tokens (not just a literal gmail branch) can contribute; InstantWinDigest labels the card honestly based on `mode`.
</objective>
