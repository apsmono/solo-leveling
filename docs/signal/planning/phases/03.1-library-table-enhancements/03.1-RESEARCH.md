## Summary

Phase 3.1 closes UI/UX and data-layer gaps in the Knowledge Library table and card views after Phase 3 shipped. The scope covers: thumbnail column, delete capability (backend + UI), inline row expand accordion, overflow menu, date formatting with relative-time tooltip, synthesize endpoint audit, and data-structure forward-compatibility.

Two plans already exist (03.1-01: DELETE endpoint + type extension; 03.1-02: dashboard TableView changes). These plans do NOT cover three decision groups from CONTEXT.md:
- **D-10:** CardView overflow menu (top-right corner, hover-reveal, Delete + Open source URL)
- **D-14 through D-17:** Inline row expand accordion in TableView (click row body, expand in-place, all fields + AI Summarize button, one-at-a-time)
- **D-20:** Relative time tooltip on hover for date column

A critical implementation gap exists: `_FileLibraryStore.delete_entry()` at `library_store.py:239` is a stub that always returns `False`. The DELETE endpoint in Plan 01 will always 404 unless this is implemented.

**Primary recommendation:** Create a new plan (03.1-03) that implements (a) `_FileLibraryStore.delete_entry()`, (b) CardView overflow menu, (c) TableView row expand accordion, and (d) relative-time tooltip on the date column.

The ⋮ menu needs a `useEffect` with `mousedown` listener on `document` to close when clicking outside. Standard React pattern:

```tsx
// Source: standard React pattern
useEffect(() => {

      setOpenMenuId(null);
    }
```

### Anti-Patterns to Avoid

- **Don't use a library for the ⋮ menu:** D-11 explicitly says inline Tailwind + state. A popover library adds bundle size for a 2-item dropdown.
- **Don't hand-roll YouTube URL parsing:** `youtubeThumbnail()` in libraryHelpers.tsx already handles `youtube.com/watch?v=` and `youtu.be/` formats. Reuse it.
- **Don't put delete state in parent:** The delete flow is fire-and-forget (D-07: wait for API 200, then remove). The parent `LibraryPage` only needs to remove the entry from its `entries` array via callback.
- **Don't add client-side sorting:** Sorting is server-side via API `sort`/`order` params. The `captured_at` column should sort by raw ISO value through the existing API mechanism, not via TanStack's `getSortedRowModel`.

## Common Pitfalls

### Pitfall 1: _FileLibraryStore.delete_entry() is a stub
**What goes wrong:** Plan 01's DELETE endpoint calls `store.delete_entry(entry_id)` which always returns `False` for the filesystem store, causing every delete to 404.
**Why it happens:** The method was declared in the abstract base but never implemented in `_FileLibraryStore` (line 239: `return False`).
**How to avoid:** Implement `_FileLibraryStore.delete_entry()` to: (1) find the file path from the index by entry_id, (2) delete the file (and parent dir if it's a bundle), (3) call `build_index()` to refresh, (4) return True.
**Warning signs:** Every DELETE request returns 404 in testing.

### Pitfall 2: Index staleness after delete
**What goes wrong:** After deleting a file, the in-memory or cached index still contains the deleted entry until rebuild.
**Why it happens:** `load_index()` may cache; `build_index()` re-scans the filesystem.
**How to avoid:** Call `build_index()` at the end of `delete_entry()` (same pattern as `update_entry()` in library.py line 339).
**Warning signs:** Deleted entry still appears in list endpoints until server restart.

### Pitfall 3: Row expand + checkbox click conflict
**What goes wrong:** Clicking the checkbox in a row also triggers the row expand toggle.
**Why it happens:** The `<tr>` has an `onClick` handler; the checkbox `<input>` is inside the row.
**How to avoid:** Add `e.stopPropagation()` on the checkbox `<input>` (already done in existing code at line 40) AND on the ⋮ menu button.
**Warning signs:** Toggling a checkbox expands/collapses the row.

### Pitfall 4: Multiple expanded rows
**What goes wrong:** Clicking different rows opens multiple accordions simultaneously.
**Why it happens:** Using per-row state instead of a single `expandedRowId: string | null`.
**How to avoid:** Single state variable: `expandedRowId`. Setting a new row auto-closes the previous one (D-17).
**Warning signs:** Multiple rows show expanded content at once.

### Pitfall 5: Menu positioning overflow
**What goes wrong:** The ⋮ menu panel extends beyond the viewport edge on rightmost columns.
**Why it happens:** `absolute right-0` positions relative to the cell, but the cell may be at the table edge.
**How to avoid:** Use `absolute right-0` with the menu panel having `w-40`; the table has `overflow-x-auto` on its wrapper, so the menu stays within scroll bounds. If needed, add `z-50` to ensure it overlays adjacent cells.
**Warning signs:** Menu clipped by table container overflow.

### Pitfall 6: Intl.RelativeTimeFormat browser support
**What goes wrong:** `Intl.RelativeTimeFormat` is not available in very old browsers.
**Why it happens:** API available in all modern browsers (Chrome 71+, Firefox 65+, Safari 14+).
**How to avoid:** The dashboard targets modern browsers (Vite 6 + ES modules). No polyfill needed. Fallback: show the formatted date string if `Intl.RelativeTimeFormat` is undefined.
**Warning signs:** Console error in Safari < 14.

### Filesystem delete implementation pattern
```python
# Based on _FileLibraryStore.get_entry() pattern (library_store.py:244-257)
# + update_entry's index rebuild pattern (library.py:339)
def delete_entry(self, entry_id: str) -> bool:
    index = self.load_index()
    for record in index.get("entries", []):
        path = record.get("path", "")
        rec_id = self._entry_id_from_path(path)
        if rec_id == entry_id:
            full_path = self._project_root / path
            if full_path.exists():
                if full_path.name == "index.md":
                    # Bundle: remove entire directory
                    import shutil
                    shutil.rmtree(full_path.parent)
                else:
                    full_path.unlink()
                # Rebuild index so subsequent reads reflect the change
                self.build_index()
                return True
    return False
```

### Relative time helper (to add in libraryHelpers.tsx)
```tsx
// Using Intl.RelativeTimeFormat (browser-native, no dependency)
export function relativeTime(dateInput: string | Date): string {
  const date = typeof dateInput === 'string' ? new Date(dateInput) : dateInput;
  if (isNaN(date.getTime())) return '';
  const now = Date.now();
  const diffMs = now - date.getTime();
  const diffSec = Math.floor(diffMs / 1000);
  const units: [string, number][] = [
    ['year', 31536000], ['month', 2592000], ['week', 604800],
    ['day', 86400], ['hour', 3600], ['minute', 60],
  ];
  for (const [unit, seconds] of units) {
    const value = Math.floor(diffSec / seconds);
    if (value >= 1) {
      return new Intl.RelativeTimeFormat(undefined, { numeric: 'auto' })
        .format(-value, unit as Intl.RelativeTimeFormatUnit);
    }
  }
  return 'just now';
}
```

## Open Questions

1. **Should _FileLibraryStore.delete_entry() also remove from vector DB?**
   - What we know: `search_library()` in `vector/search.py` may have indexed the entry's embeddings
   - What's unclear: Whether deleting the file automatically invalidates vector search results
   - Recommendation: Defer to Phase 5/6 — vector search returns by entry_id, and a deleted entry's ID won't match new queries. If stale vector results cause issues, add a vector cleanup step later.

2. **Should the expanded row's AI Summarize button update the entry in the parent state?**
   - What we know: `synthesizeEntry()` returns `{ status, answer, sources }` — the answer is the AI summary
   - What's unclear: Whether to store the summary back to the entry (via `updateLibraryEntry`) or just display it in the expanded panel
   - Recommendation: Display only in the expanded panel for now. Persisting AI summaries to the entry is a Phase 5 concern (D-14 says "AI summary (if present)" suggesting it may already exist on the entry).

3. **Does the ⋮ menu need to work on mobile (touch)?**
   - What we know: The dashboard is used on desktop primarily
   - What's unclear: Whether touch events need special handling for the menu
   - Recommendation: Use `onClick` (works for both mouse and touch). The `mousedown` click-outside listener also fires for touch on most mobile browsers. No special handling needed for v1.
