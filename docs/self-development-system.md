# Self-Development System

## Purpose

Define the operating system for personal growth so actions, skill-building, and reviews are aligned.

## Current Objective

- **Primary growth aim:** Become an AI-native engineer and solopreneur who builds and ships autonomous systems.
- **Why it matters now:** The window for early adoption of multi-agent AI workflows is closing. Building the solo-leveling brain, mastering agent orchestration, and creating income-generating products now creates compounding advantage.
- **Time horizon:** 12-month sprint to product-market fit for at least one income-generating asset.

## Identity Targets

- **Person I am becoming:** A developer who ships complete products end-to-end — backend, frontend, AI integration, and deployment — without relying on large teams. Someone who uses AI as a force multiplier, not a crutch.
- **Core principles to reinforce:**
  - Ship fast, iterate publicly.
  - Document everything (the next agent needs to know what I knew).
  - Build systems that work while I sleep (autopilot, scheduled workflows, passive assets).
  - Learn by building, not by consuming.
- **Behaviors to stop tolerating:**
  - Starting new projects before finishing current ones.
  - Manual repetition of tasks the brain could automate.
  - Analysis paralysis on deployment decisions.

## Active Constraints

- **Time:** Day job limits coding to evenings and weekends. Max 20 hours/week deep work.
- **Capital:** Bootstrapped. No paid marketing. Infrastructure cost must stay under $50/month.
- **Location:** Based in Indonesia. Payment processors, hosting, and API availability differ from US defaults.
- **Solo operator:** No co-founder or employee. Every system must be self-managing or AI-managed.

## Execution System

- **Daily non-negotiables:**
  - 1 commit to solo-leveling or a submodule (even if small).
  - Review `AI_CONTEXT.md` and current priorities.
  - Process any Telegram bot commands or dashboard actions.
- **Weekly growth actions:**
  - One deep-learning session (new tech, pattern, or architecture).
  - One marketing/content action (blog post, social share, documentation).
  - Review and update this document.
- **Monthly deep-work focus:**
  - Dedicate one full weekend to a single major feature or integration.
  - Audit all active projects for drift from original intent.
  - Plan next month's highest-leverage action.
- **Recovery rules:**
  - No coding after 10 PM (sleep > ship).
  - One full day per week with zero project work.
  - If burnout signals appear (irritability, avoidance, physical fatigue), pause all new features for one week and focus only on maintenance.

## Failure Patterns

| Pattern | Trigger | Prevention Rule |
| ------- | ------- | --------------- |
| Shiny object syndrome | Seeing a new framework/tool trending | 48-hour cooling-off period before adopting anything new. Must document why existing stack cannot solve the problem. |
| Perfectionism blocking ship | Feeling a feature "isn't ready" | Define "good enough" criteria before starting. Ship when criteria met, polish in follow-up. |
| Context switching drain | Working on 3+ projects in one session | Use the brain's `/command` to set a single focus. Finish one context before switching. |
| Documentation debt | "I'll document it later" | Document in the same commit. AI can generate docs — use it. |
